## 2026-10-03：FIX-013 公开评测等待遮罩改为聊天式实时进度

## 2026-10-03：FIX-014 短需求评测过度澄清与行为级设计策略

- **现象与证据**：[真实报告 BR-dbcf50c0bc70](../data/benchmark_reports/BR-dbcf50c0bc70.json) 中 102 在需求分析后第 2 步等待业务输入，103/104 在第 4 步等待模块确认并混入业务追问，均无用例、无用例语义评审、无技术失败或降级。103 原文仅要求注册为订户，却追问支付、年龄和法规等扩展。此前 FIX-012 已明确未处理这类澄清，本项补齐该策略；原报告不改写。
- **确认根因**：评测目标笼统要求缺业务依据就澄清；分析歧义为自由文本，未区分执行准备和预期行为阻塞；所有 clarification 统一阻塞，通用结构评审还固定要求功能/边界/异常三类，可能迫使短需求扩展范围。模块确认与业务问题合在一段提问中，也容易误以为模拟确认会回答全部问题。
- **实现**：新增 `app/clarification_policy.py`，以 strict / evidence_only 区分面向执行与按原文生成行为级设计；需求分析、工具研究、模块规划/评审、用例生成/修复/评审与 Supervisor 共用范围契约。`models.py` 新增带分类、依据、影响范围与理由的澄清项；行为级分析检查原文引文和引用，不静默接受未分类歧义。严格模式仍为普通工作台、旧项目和未传参数 API 的默认值，网页 EBT/StorySeek 推荐 evidence_only，组件套件拒绝不适用策略。
- **门禁与编排**：`review_policy.py` 在行为级模式下仅将具备运行时核对依据的 execution_detail/out_of_scope 澄清视为非阻塞；真实缺陷、高危、关键歧义、旧/不完整分类及 review_incomplete 保持阻塞。行为级不普遍强制三类用例，但原子需求覆盖、有效引用与预期结果检查保留。Supervisor 拒绝仅为实现细节而暂停，模块确认问题单独生成；分析关键歧义即使后续评审满分也不能 finish。模拟确认不会跨过已记录的关键歧义或高危模块评审，也不生成业务答案。策略保存到项目和运行，变更后旧运行不能直接续跑。
- **报告与使用**：修改 benchmark_execution、public_benchmarks、orchestrator、api、supervisor_models 及工作台 HTML/JS；同步 README 和 [公开评测说明](benchmarks.md)。报告新增策略、设计层级、执行准备状态、分析/评审澄清项、受阻需求和未关联用例的需求；页面「范围与执行准备」可展开查看。重启并刷新后，新建 EBT 评测，选择 Agentic、按原文生成行为级用例、模拟确认模块。旧暂停报告不自动迁移策略。
- **验证与过程**：新增 `tests/test_clarification_policy.py` 13 项，更新已有 API 转发断言；最终完整隔离回归 **209 项通过（29.775 秒）**。模拟 Workflow/Agentic 均验证接口缺口保留但行为级评审可完成；矛盾/高危模块不自动确认，缺陷/超时/无效依据继续阻塞，末尾有足够步骤收尾时不允许无故要求预算，策略进入各层提示词和报告、指纹/历史账本语义一致。首轮因旧 API 断言未包括新默认参数失败，随后新测试使用的 mock.kwargs 写法与本机版本不兼容，均修正后通过；不是模型真实调用失败。[本地回归输出](../.local-private/clarification-tests-20261003.txt)。Python 编译、JS 语法和流解析检查通过。
- **页面与边界**：临时数据目录、无模型凭证的合成 EBT 演示中，Agentic 6 步完成，页面明确显示行为级及未验收可执行性，浏览器 error/warn 为空。[离线页面证据](../.local-private/clarification-policy-ui-20261003.png)。未发起真实 GLM 请求，102/103/104 在新策略下的实测待验证；引文校验不能证明全部语义推断正确，仍需 Critic 与人工复核。行为级通过不等于可执行验收、完整业务覆盖或模型能力提升；真实核心歧义仍可能暂停，页面暂不提供直接回答入口。
